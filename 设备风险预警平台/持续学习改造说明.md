# 模型持续学习与管理员发布流程说明

## 完整工作流程

1. 系统在设备预测时自动保存遥测快照，同一设备、同一采样时间去重。
2. 工作人员在“模型训练中心”对样本反馈：正常（标签 0）、确认故障（标签 1）、确认异常但未确认故障（暂不训练）或暂不确定。
3. 管理员检查已审核反馈，确认样本标签可信。
4. 管理员点击“使用已审核数据训练新模型”。系统合并原始训练数据和已审核反馈，训练候选 HGBT 模型并自动评估。
5. 评估通过的候选模型进入“待管理员审批”状态，不会自动替换线上模型。
6. 管理员在“模型迭代历史与发布审批”中点击“审批并发布”，确认后才切换线上模型。
7. 如果新模型上线后表现异常，管理员可在历史记录中选择之前已发布的版本回滚；初始 `V1.0-基础模型` 也保留为回退选项。
8. 评估未通过的候选模型标记为“评估未通过”，不能通过正常审批按钮发布，线上模型保持不变。

## 管理员模式说明

当前版本按单机管理员模式设计：模型训练中心提供完整的样本审核、训练、审批发布和回滚操作，发布审批记录会保存“管理员”和审批时间。项目原本没有账号登录体系，因此本次没有虚构多用户身份认证；如果平台要部署到多人共用的局域网或生产环境，还需要增加账号登录、角色权限校验和操作审计，不能仅依靠页面按钮隐藏来保护管理接口。

## 样本与训练规则

- 只有已审核的正常/故障反馈参与监督训练。
- 反馈标签覆盖同一设备、同一采样时间的原始 `fault_label`；未匹配到原始数据的反馈快照才会追加，避免重复计数。
- “确认异常但未确认故障”不会被错误地标为故障 1。
- HistGradientBoosting 不支持 `partial_fit`。本次采用“持续积累反馈 + 批量重新训练”，不是每条反馈即时修改模型参数。
- 训练优先按时间切分训练集和测试集，并与当前线上模型比较故障召回率和 ROC-AUC；未达到保护门槛时不进入审批发布状态。

## 使用步骤

1. 解压完整项目，按原方式运行 Windows 启动脚本或 `python dashboard.py`。
2. 进入“模型训练中心”，检查并保存工作人员反馈。
3. 以管理员身份发起模型训练。
4. 训练通过后，在模型迭代历史中点击“审批并发布”。
5. 如需回退，在历史记录中点击目标已发布版本的“回滚到此版本”。

## 重要注意事项

- 初始训练标签来自数据库 `run_simulation_log.fault_label`。请确认原始标签是否可信；若只是仿真标签，指标只代表仿真数据拟合效果，不能直接代表现场故障预测能力。
- 故障样本占比较低时，应重点观察故障召回率、精确率、F1 和 ROC-AUC，不要只看准确率。
- 原始模型由 scikit-learn 1.9.1 生成，`requirements.txt` 固定为该版本以减少反序列化版本不一致问题。
- 为避免继续分发原有明文 AI 服务密钥，`agent_config.json` 中的 `api_key` 已清空。需在本机配置新密钥；未配置时 AI 问答不可用，但 HGBT 预测、训练和发布不受影响。
