# 设备风险预警平台 · UI 页面重组设计

日期：2026-11-19　状态：已与用户逐节确认（页面归属与路由 / 页签组件与内容归位 / 联动异常态与验证口径）

## 1. 目标与判定标准

现在 5 个页面、导航 5 项，`model-center.html` 一节里塞了 6 个互不相干的分区，`devices.html` 塞了 3 个不相干对象，人工核查有 `/report` 和「待确认运行样本」两个入口。结果是同一件事要认两次地址，训完模型要跨页找数据出处。

重组后按「看 → 办 → 录 → 训」四步动线各一页，页内用页签切对象；人工核查只剩一个入口页；每条说明文案只有一个来源。判定标准：

- 导航 4 项，页面文件 4 个（`risk.html` 消失，旧地址 302）；
- 任意一个后台操作（录事件、反馈、训练、审批、回滚）从首页出发最多 2 次点击可达；
- 后端接口、数据库表、状态机零改动；真实台账逻辑内容零改动；
- 全量沙箱探针（现有 15 支 + 新增 3 支）失败合计 0。

## 2. 范围之外

本轮明确不做，避免顺手扩大改动面：

- **不合并两套模型的审批状态机**（B2）：`models/active_model.json` 指针与 `health_model_runs.status` 仍是两套词汇（`pending_approval` 与 `candidate/retired/dry_run`），`model-center.js` 里两个状态映射表保持分开。
- **不动 B4/C4**：这两项与 B2 一样单独排期。
- **不引入登录与权限**：保持 0.0.0.0 免登录（项目红线）。
- **不改后端**：`/api/daily-report`、`/api/model-feedback`、`/api/fault-events`、`/api/lifecycle`、`/api/model-*`、`/api/health-model-*` 的路径、请求体、返回体、截断线（样本 500 / 事件 5000）全部原样。
- **不做按页裁剪抽屉**：见 §5。

## 4. 页签组件（新增，全站唯一一份）

`common.js` 增加 `initTabs()`，由 `boot()` 在 `injectNav()` 之后调用；`app.css` 增加 `.tabs`、`.tab-btn`、`.tab-panel` 三组规则（当前 CSS 与 JS 里都未占用 `.tabs` / `[data-tab]`，无命名冲突）。

约定：

- 标记：`<div class="tabs" role="tablist">` 内含按钮 `<button class="tab-btn" data-tab="info">设备信息</button>`；面板 `<section class="tab-panel" id="tab-info" role="tabpanel">…</section>`，面板 id 为 `tab-` + 页签 id，与按钮 `aria-controls` 一致。每页一组，`initTabs()` 按页面里出现的 `.tabs` 各自初始化，不再加分组属性。
- 状态：`aria-selected="true"` 只给活动按钮；非活动面板置 `hidden` 属性（不是 `display:none` 遮罩），保证不参与命中测试与读屏朗读。
- 持久化：切换写 `location.hash = "tab=<id>"`；进页时读 hash 决定落位。hash 缺失、值非法、或指向本页不存在的页签 → 落第一个页签，不报错、不白屏。
- 键盘：`role="tablist"` + 左右方向键切换 + Home/End 跳首尾，焦点留在按钮上（不自动激活面板内容）。
- 移动端：≤640 px 时页签栏 `overflow-x:auto` + `scroll-snap-type:x proximity`，不换行、不折叠成下拉；按钮高度 ≥44 px。
- 数据：切换只切显示，**不触发重新请求**。现有 `App.boot()` 的 15 秒兜底轮询、`visibilitychange` 回页补拉（`common.js:1120`、`:1126`）继续负责刷新，切页签打不到空接口。

内容归位的取舍：

- 风险概览：`#stats` 统计条只出现在「风险看板」页签；三个 `/api/export` 下载链接跟着「归因与治理」页签走；卡片上的「AI 解读」按钮与校准入口不变。
- 今日核查：两页签并列，各自带自己的筛选（设备核查沿用分级/风险筛选，样本反馈沿用 `pending / reviewed / all`）；两个后端写入路径互不干涉。
- 设备台账：`EV.mount()` 及其 5 个容器（`evHead` `evCounts` `evForm` `evPreview` `evList`）搬进第 3 页签，`events.js` 随页面加载；`importDrawer` 的「导入数据」按钮留在设备信息页签内。
- 模型训练：状态卡（`mcStats`）与「重新训练」（`mcTrain` + `mcTrainResult`）并到第一页签；删掉「待确认运行样本」「训练数据」两个分区（已分别搬走）。

## 5. 分页与抽屉

现在四个列表一次全渲染，页面会随数据变长而不可用。补齐前端分页（服务端截断线不动）：

| 列表 | 每页 | 实现位置 |
|---|---|---|
| 设备核查卡（`/api/daily-report` items，无服务端上限，等于风险设备数） | 10 | `report.js`，走 `bindPager()` + `S.pager` |
| 运行样本（`/api/model-center` samples，服务端 500 上限） | 20 | `model-center.js`，同上 |
| 维护历史记录（`/api/work-records`，服务端 `limit=5000`） | 20 | `page-devices.js`，同上 |
| 故障事件 / 生命周期（`/api/fault-events`、`/api/lifecycle`，服务端 5000 上限） | 20 | `events.js`，同上 |

`bindPager()`（`common.js:322`）现在按 `data-pager` / `data-page` / `data-size` 委托后固定调全局 `render()`，而 `render()` 只画看板卡片与台账表，画不到上面这四个各自取数的列表。改法只一处：`S.pager` 的每一项支持可选 `draw` 回调，`bindPager` 命中时该项有 `draw` 就调 `draw()`，没有就照旧走 `render()`。四个列表于是共用同一套 `App.paginate` / `App.pagerHTML` / 委托逻辑，不在四个文件里各写一份翻页。每页条数下拉沿用现有 `[data-size]` 行为：改条数回第一页。

抽屉维持 `injectChrome()` 一处统一注入四个（详情 / 校准 / 问 AI / 导入）。理由：其中三个的触发点在每页都存在（卡片、表格行、右下「问 AI」悬浮球），按页裁剪要在四处加条件，收益只有几百字节 DOM，不划算。

## 6. 跨页联动与说明文案

站内硬编码链接三处跟着改：

| 位置 | 现在 | 改成 |
|---|---|---|
| `common.js:344` 空态「去设备台账录入第一台」 | `href="/devices"` | 不变 |
| `common.js:353` 空态「智能分析（归因与治理方案）」 | `href="/risk"` | `href="/#tab=analysis"` |
| `devices.html:31`「看智能分析 →」 | 跳 `/risk` | `href="/#tab=analysis"` |

台账页的按钮切不到概览页的页签（页签状态是页内的），所以这一处保留跨页跳转、只把地址换成带 hash 的新位置；带 hash 的普通链接不需要 JS 也能走，比给 `initTabs()` 再开一个外部激活接口划算。

必须新增的一条引导：模型训练页第一页签顶部加一句带链接的提示，指向 `/devices#tab=events`。事件计数与「还差 N 条」文案搬到台账后，审批人在训练页必须还能下钻到数据出处，否则「训不动」变成断链。

说明文案单一来源：`HM_SCOPE_NOTE`（`common.js` 的 `data-hm-note` 填充）继续一处维护；搬家的分区里那些解释「故障事件是什么」「为什么两条列表要分开」的 tip 文字随分区一起搬，不在新页重复写第二份；训练中心被搬空的分区其 tip 一并删除。

保留的既有行为：校准/台账保存后立即重算、`/api/state` 15 秒兜底轮询、`visibilitychange` 补拉、样本保存后筛选从 `pending` 自动转 `reviewed`（`model-center.js:171`）、反馈保存只打标签不触发训练的提示。

打印：`今日核查` 的「打印 / 保存为 PDF」按钮只在设备核查页签出现；`@media print` 增加隐藏 `.tabs` 与 `[hidden]` 面板，纸面内容与现在逐字一致（`report.html` 内联 `<style>` 里的 `.report-*` 与 print 规则随页面并入，不搬进 `app.css`——只有这一页用）。

## 7. 异常态

- hash 非法或缺失 → 第一个页签；
- 某面板接口 500 或网络断开 → 只在该面板内出 `.warn`（沿用 `report.js` / `model-center.js` 现有失败文案格式），其他面板照常可用；
- 列表为空 → 沿用现有 `.empty` 文案，随分区搬家；
- 两个模型未上线 → 台账与概览「未上线」chip、`data-hm-note` 说明照旧；
- 旧 `/risk` 书签 → 302 到新位置，不 404；
- 打印时另一面板不进纸；
- 无登录、无权限分支（本轮不引入）。
